# 算法说明：从全量动态规划到阈值剪枝

## 基线方法

普通 Levenshtein 编辑距离使用动态规划，时间复杂度为 `O(m × n)`。对词库中的每个词都计算完整距离，
哪怕该词显然不可能达到设定阈值。

## 本项目的四个改进

1. **长度差预筛选**：编辑距离至少为 `abs(len(a) - len(b))`。若长度差已经大于阈值 `k`，直接返回 `k + 1`。
2. **带状动态规划（banded DP）**：若目标距离不超过 `k`，有效路径只能位于主对角线左右 `k` 格内，
   只计算这一区间，避免填充整个矩阵。
3. **行最小值提前终止**：如果当前整行可达状态的最小距离已经大于 `k`，后续无法回到阈值内，提前结束。
   这条依赖「行最小值随行号单调不减」的性质，测试用穷举差分覆盖了它。
4. **按标准化长度分桶**：索引建立时预处理 Unicode 文本并按长度分组；查询时只扫描长度差不超过阈值的桶，
   同时复用已经标准化的文本。

## 两个回退规则

优化不是无条件的，两条回退规则负责「别在没收益的地方付代价」：

1. **带宽覆盖整个矩阵时用普通 DP**。判据是 `2k + 1 ≥ 短边长度` —— 带子已经覆盖每一列，
   再算边界就没有意义了。典型场景：三个汉字的人名配 `k=2`，带宽 5 格而矩阵只有 3 格宽。
   实测单次调用 1.90 µs（普通 DP）vs 2.50 µs（带状）；端到端从 0.91×（比基线慢）
   回到 1.08×。
2. **所有条目都是候选时跳过桶**。若 `[len-k, len+k]` 覆盖了全部条目，遍历桶只会多一层间接寻址；
   此时直接线性扫描。典型场景：2–3 个字的人名语料只有两种长度。

第 2 条同时修掉了一个边界问题：早期实现用 `range(len-k, len+k+1)` 枚举长度，
`k` 很大时会空转 O(k) 次；现在只遍历实际存在的长度键。

## 结果收集

扫描阶段只累积 `(distance, index)` 元组，最后按 `limit` 分两种情况：

- `limit=None`：全量排序，物化全部 `Match`。
- `limit=n`：用 `heapq.nsmallest` 取前 `n` 个，只为入选条目构造 `Match`。
  命中集远大于 `limit` 时（例如 2 字名查询几乎全中），这一步省掉大量对象构造。

顺序始终是 `(distance, index)`，因此相同的 `distance` 会保持原始输入顺序。

## 文本规范化

默认 NFC + `casefold()`：

- `café` 与 `cafe` + U+0301 相等，`Straße` 与 `STRASSE` 相等。
- 不剥重音、不转写文字系统，避免把本来不同的词合并。

可选 `compatibility=True` 改用 NFKC，额外折叠：

| 输入 | NFC（默认） | NFKC（opt-in） |
|---|---|---|
| `ＡＢＣ` | `ａｂｃ` | `abc` |
| `ｶﾀｶﾅ` | `ｶﾀｶﾅ` | `カタカナ` |
| `①` | `①` | `1` |
| `㈱` | `㈱` | `(株)` |
| `ﬁ` | `fi` | `fi` |

后三行是它默认关闭的原因：折叠会合并语义上可能不同的字符。

## 正确性约束

`levenshtein_bounded(a, b, k)` 返回真实距离（当距离不超过 `k` 时），否则返回 `k+1`。
测试对确定性随机样本比较它与未剪枝实现的结果；检索基准还会对比两种实现的完整命中列表，
不一致时脚本直接失败。

维护者另外跑过（脚本未入库）的更强验证：二元字母表 ≤7 字符、三元字母表 ≤4 字符的全对全穷举，
k=0…7，共 622,687 次比对 0 失败；640 条脏语料（空串 / 全角 / 半角假名 / ß / İ / ZWJ emoji）
× 527 条查询 × 5 个阈值，共 4,216 次检索比对 0 失败。

## 适用边界

- 最适合「允许少量输入错误」的名称、商品标题、文件名、命令和中小规模词库。
- 分桶只利用长度，语料长度集中时收益归零；此时本索引与朴素扫描同速，不会更快。
- 对超大语料，逐个扫描候选仍是线性的；下一阶段可研究 SymSpell 删除词索引、n-gram 倒排索引或 Trie/FST。
- 文本按 Unicode code point 比较；不会把拼音、日文读音或跨语言同义词当作相等，也不保证组合 emoji
  作为单个可见字符计数。
- `max_distance` 越大，带状 DP 的优势越小；超过字符串长度后自动走普通 DP。
